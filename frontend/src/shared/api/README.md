# Capa de API Compartida (Shared API Layer)

Este directorio contiene toda la infraestructura de comunicación HTTP del frontend de DockUS con el backend REST. Centraliza el cliente Axios configurado con interceptores de autenticación, auto-refresh de tokens JWT y normalización de errores, junto con fachadas tipadas organizadas por dominio de negocio. Ningún componente del frontend debe usar Axios directamente; toda comunicación con el servidor pasa a través de estas fachadas para garantizar consistencia en autenticación, manejo de errores y tipado.

## Archivos y Responsabilidades

### Infraestructura HTTP
- **`http.ts`**: Módulo central que crea y configura la instancia Axios compartida (`http`) con `baseURL` dinámica desde `VITE_API_BASE_URL`, timeout de 30 segundos, y headers anti-cache. Gestiona el estado de tokens de autenticación (`accessToken`, `refreshToken`) mediante funciones `setAccessToken`/`setRefreshToken` consumidas por el `SessionContext`. Implementa un interceptor de peticiones que inyecta automáticamente el header `Authorization: Bearer` con el token vigente. El interceptor de respuestas maneja el flujo completo de auto-refresh ante errores 401: detecta si hay refresh token disponible, evita carreras con un flag `isRefreshing` y una cola de suscriptores, ejecuta el refresh contra `/auth/refresh`, actualiza los tokens en memoria, notifica a los listeners suscritos (`subscribeTokenUpdate`) para que el `SessionContext` persista los nuevos tokens, y reinicia las peticiones encoladas. Si el refresh falla, limpia tokens y notifica a los listeners de warning (`subscribeAuthWarning`) para mostrar un aviso de sesión expirada. Los errores de red se normalizan a una estructura `ApiErrorPayload` uniforme.
- **`query-params.ts`**: Exporta dos funciones utilitarias para la serialización de parámetros de consulta. `toParams` convierte un objeto con valores `string | number | undefined` en `URLSearchParams`, filtrando automáticamente los valores `undefined` o vacíos para generar URLs limpias. `normalizeStringArray` normaliza arrays de strings (trimming y filtrado de vacíos), usada por las fachadas de asignaciones y grupos para sanitizar payloads antes de enviarlos al backend.
- **`services.ts`**: Módulo agregador de compatibilidad que re-exporta todas las fachadas de dominio desde un único punto de importación. Permite que código legacy o componentes existentes importen todas las APIs desde `shared/api/services` sin modificar sus imports. La implementación real reside en los módulos individuales por dominio; este archivo se mantiene exclusivamente para evitar migraciones masivas de imports.

### Clientes de API por Dominio
- **`authApi.ts`**: Fachada tipada para los endpoints de autenticación (`/auth/*`). Expone métodos `register` (registro de nuevo usuario con email, password, nombre y apellidos), `login` (inicio de sesión con credenciales), `profile` (obtención del perfil del usuario autenticado con `userId`, `email` y `role`), y `refresh` (renovación de tokens JWT). Retorna objetos `AuthResponse` tipados que son consumidos directamente por el `SessionContext` para crear registros de sesión.
- **`usersApi.ts`**: Fachada tipada para la gestión de usuarios (`/users/*`). Implementa CRUD completo: `list` (listado paginado con filtros por rol, estado y búsqueda textual), `detail` (detalle por ID), `create` (creación con rol y estado opcionales), `update` (actualización parcial), `updateStatus` (cambio de estado: ACTIVE/SUSPENDED), `remove` (soft-delete) y `restore` (restauración). Retorna entidades `UserEntity` tipadas y soporta paginación con `PaginatedResponse`.
- **`projectsApi.ts`**: Fachada tipada más extensa del sistema, cubriendo todos los endpoints del módulo de proyectos (`/projects/*`). Incluye CRUD básico (list, detail, create, update, remove, restore), cambio de estado (`updateStatus`), gestión de suites de tests docentes (upload, get, remove, preview), resúmenes de progreso y gradebook con filtros en cascada (estado de entrega, outcome del builder, entregas tardías, grupo), exportación a CSV/Excel como Blob, quality insights por proyecto/categoría/alumno, gestión de problemas operacionales (detección y reconciliación), y gestión de profesores colaboradores (addTeacher, removeTeacher). Utiliza `toParams` para serializar los filtros de consulta.
- **`assignmentsApi.ts`**: Fachada tipada para la gestión de asignaciones de proyectos (`/projects/:projectId/assignments/*` y `/assignments/*`). Expone `bulkAssign` (asignación masiva con sanitización de arrays mediante `normalizeStringArray`), `listByProject` (listado de asignaciones por proyecto con soporte de `AbortSignal` para cancelación), `listMine` (asignaciones propias del alumno autenticado), y `revoke` (revocación de asignación). Retorna tipos `BulkAssignResponse` y `ProjectAssignmentEntity`.
- **`groupsApi.ts`**: Fachada tipada para la gestión de grupos docentes (`/groups/*`). Implementa `list` (listado completo de grupos con soporte de `AbortSignal`), `create` (creación con nombre, código y descripción opcionales), `listEnrollments` (matriculaciones de un grupo), `bulkEnroll` (matriculación masiva con sanitización de arrays y soporte de `rawInput` para importación de texto libre), `revokeEnrollment` (revocación de matriculación), `update` (actualización parcial), y `remove` (eliminación). Retorna tipos `CourseGroupEntity`, `GroupEnrollmentEntity` y `BulkGroupEnrollResponse`.
- **`deliveriesApi.ts`**: Fachada tipada para la gestión de entregas (`/deliveries/*`). Cubre CRUD completo: `list` (listado paginado con filtros por proyecto, asignación, autor, estado y ordenación), `detail`, `create` (creación con `assignmentId`, estado y notas opcionales), `update` (actualización parcial), `updateStatus` (transición de estado), `updateGrading` (calificación y notas del evaluador), `remove`, `restore`, y `preview` (previsualización del contenido entregado como array de `{path, content}`). Retorna tipos `DeliveryEntity` y `PaginatedResponse`.
- **`storageApi.ts`**: Fachada tipada para la gestión de objetos de almacenamiento (`/storage/*`). Implementa `list` (listado paginado con filtros por entrega, proyecto, rol de activo, uploader y rango de fechas), `detail`, `upload` (subida de archivo con `FormData` incluyendo `deliveryId`, `logicalName`, `logicalPath`, `contentType`, hash SHA-256 y tamaño opcional), `createDownloadUrl` (generación de URL presignada), `remove` (eliminación lógica), `purge` (eliminación física, solo ADMIN), y `restore` (restauración). Retorna tipos `StorageObjectEntity` y `DownloadUrlResponse`.
- **`builderApi.ts`**: Fachada tipada especializada para el pipeline de construcción y evaluación automática (`/builder/*`). Expone operaciones de ejecución (`runForDelivery`, `cancel`), consulta de ejecuciones (`detail`, `listByDelivery` con paginación), streaming de eventos de ejecución (`listEvents` con `afterSequence` para polling incremental), gestión de artefactos de evidencia (`listEvidenceArtifacts`, `getEvidenceDownloadUrl`, `getEvidenceContent` como texto, `getEvidenceContentAsBlob` como binario), quality insights por asignación, y un sistema de chat integrado (`getChatMessages`, `sendChatMessage`) que permite interacción conversacional con el builder durante una ejecución. Retorna tipos especializados como `BuildRunEntity`, `BuildRunEventsPage`, `EvidenceArtifactDto` y `BuildRunChatMessage`.
